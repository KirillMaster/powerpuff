# Что переносится из bob-pipeline и что нет

Критерий: остаётся то, что на бенче или в истории проектов дало измеримую пользу и не требует модели там, где хватает скрипта.

| Из bob-pipeline | Решение | Основание |
|---|---|---|
| Механические гейты (формат, линтер, архитектура, тесты) как условие «готово» | берём: `forge_check.py` | детерминированно, дёшево |
| Конфиг проекта `.claude/bob-pipeline.yaml` (команда тестов, включённые инструменты) | не читается: файл лишь указан в промпте аудита как подсказка для черновика гейтов, когда `powerpuff.yaml` нет; источник гейтов — профиль `powerpuff.yaml` | профиль утверждает человек, модель гейты не выбирает |
| Продолжение после сбоя и ожидание лимита подписки, накопительный бюджет | берём: `forge_run.py` | автономный прогон без человека |
| Запрет ослаблять гейты и трогать тесты | берём: замороженные хэши, восстановление из git | модель иначе подгоняет тесты |
| Независимая проверка покрытия требований | берём как одну приёмку сильной моделью в свежем контексте | одна проверка вместо пяти ролей |
| Трассировка требование → тест | берём: идентификаторы `R<n>` в приёмочных тестах | проверяется скриптом |
| Гейты K2–K4 (красный тест на чистой базе, классификация отката, дифф публичного API), `ci_gates.py` | кандидаты: переносим по одному, только с замером пользы | на бенче отдельно не измерялись |
| Метрики прогона | упрощаем: стоимость по моделям и этапам в `state.json` | хватает для отчёта |
| Пять ролей (Specifier, Coder, Architect, Hardener, QA) на каждый слайс | не берём | пилот: качество 0.70–0.78 против 0.94–1.0 у plain при цене в 5–20 раз выше |
| Gherkin и QA-процедуры как обязательный слой | не берём | дублирует спеку yamlkit, пользы не показал |
| Мутационное тестирование в цикле | не берём по умолчанию | данных о пользе в агентном цикле нет; дорого |
| Модель-оркестратор | не берём | $11.42 против ~$1 |
