# Эффективность powerpuff (движок `plain`) — отчёт 2026-11-19

Вопрос: даёт ли powerpuff (`forge_run.py --engine plain`, по умолчанию) лучше результат, чем обычный Claude Code (одна сессия Opus без харнесса), и сколько это стоит.

## Итог
| Что | plain (Claude Code без харнесса) | powerpuff `plain` |
|---|---|---|
| Качество поведения (скрытые тесты), 6 задач с результатом у обоих | 0.968 | **0.996** |
| Задачи, где поведение лучше / равно / хуже, чем у plain | — | 3 / 3 / 0 |
| Цена на задачу, $ | 0.67 | 1.46 (×2.2) |
| Время на задачу, мин | 8 | 19 (×2.3) |
| Провалы движка | — | 2 из 8 (TS: нет зависимостей в репо; исправлено, не перемерено) |
| Свежий репозиторий без профиля (Python, 4 требования) | — | `FORGE: done` за 88 с, $0.50, 7 гейтов из пресета, тесты красные до кода и зелёные после |
| Свежий клон TypeScript без `node_modules` и без профиля (4 требования), после исправлений | — | `FORGE: done` за 121 с, $0.56: `setup` поставил зависимости, все 6 гейтов пресета активны (typecheck, build, tests, …), покрытие требований 4/4 |

Вывод: на задачах, которые дошли до результата, powerpuff не проиграл plain ни разу и выиграл на трёх из шести; на них plain терял требования, а замороженные приёмочные тесты и гейты эти потери поймали. Цена — примерно вдвое больше денег и времени. При n=1 на задачу разница по качеству внутри шума (+0.028, доверительный интервал пересекает ноль), разница по цене — нет.

**Когда powerpuff, когда plain**
| Ситуация | Режим |
|---|---|
| Работа без присмотра (автономный прогон, очередь спек), нужна проверяемая «готовность» | powerpuff: замороженные тесты, гейты скриптом, отчёт с доказательствами |
| Многотребовательная спека, где пропуск требования дорог | powerpuff: тесты по каждому `R<n>` до кода |
| Маленькая правка рядом с человеком | plain: дешевле вдвое, качество то же |

## Как мерили
| Параметр | Значение |
|---|---|
| Набор | 8 задач из реальных рабочих репозиториев (Python ×4, TypeScript ×3, C# ×1) со скрытыми приёмочными тестами; ещё 3 задачи C# и многоэтапный проект не успели пройти (прогон остановлен нехваткой памяти на хосте) |
| Повторы | k=1 на задачу (plain — те же задачи из прогона 2026-11-17) |
| Изоляция | Docker, одинаковые образы и лимиты; оценка — скрытые тесты, регрессия, гейты, судья (`bench/scripts/protocol_verdict.py`) |
| Модель | Opus в обоих вариантах |
| Цена | по `total_cost_usd` CLI; для сессий с `--resume` считается приращение (см. «Ошибки, найденные бенчем», п. 3) |

## Ошибки, найденные бенчем (все исправлены, покрыты тестами)
| # | Ошибка | Следствие | Исправление |
|---|---|---|---|
| 1 | Гейт дубликатов ругался на клон внутри замороженных тестов | 4 пустых фикс-раунда, ×4 к цене | клоны внутри замороженных тестов не считаются; копипаст из них в код — считается |
| 2 | Фикс-раунд без изменений повторялся до лимита | лишние сессии | раунд без изменений в дереве завершает цикл |
| 3 | `claude -p --resume` отдаёт кумулятивную цену сессии, драйвер её суммировал | цена завышалась; у forge в бенче ×1.6–2.2 | считается приращение; пересчёт forge — в отчёте бенча |
| 4 | Черновой профиль: гейт без инструмента валил прогон до первой сессии | провал TS-задач (ts-1, ts-2) | гейт без инструмента в черновике исключается и называется в отчёте |
| 5 | Нет установленных зависимостей (свежий клон) → тест-гейты красные на базе и исключаются | на этих задачах powerpuff проверял только статические гейты | ключ `setup` в профиле, пресеты ставят зависимости до проверки базы (после прогона, не перемерено) |
| 6 | Требования `R<n>` спеки не сверялись с тестами | отчёт «requirements: 0» | id без теста → один ход «допиши тесты», остаток — `uncovered` в отчёте |

## Ограничения отчёта
| Ограничение | Влияние |
|---|---|
| k=1, 6 пар задач | разница по качеству в пределах шума; нужен прогон k=2 на всех 12 задачах |
| В образах бенча у Python- и TS-задач тест-гейты были исключены (зависимости не установлены, п. 5) | преимущество powerpuff на этих задачах — от замороженных тестов и вопросов, не от гейтов; с `setup` ожидается больше |
| Пп. 4–6 исправлены после прогона | ts-1, ts-2 на бенче не перемерены; `setup` проверен реальным прогоном на свежем TS-клоне (таблица «Итог») |
| Многоэтапный проект и 3 задачи C# не прошли | нет данных о доработках поверх своего кода |

## Как работать с Claude эффективно (по всем замерам)
| Правило | Почему (замер) |
|---|---|
| Одна сессия Opus на срез спеки, без ролевого конвейера | ролевой конвейер хуже plain (Δ −0.28), многосессионный forge — то же качество за ×3–4 |
| Перед кодом — вопросы по неоднозначностям и приёмочные тесты, которые модель не может править | powerpuff поймал пропущенные требования на 3 из 6 задач |
| «Готово» решают коды выхода команд, а не слова модели | все 6 «done» powerpuff подтверждены скрытыми тестами: 5 — полностью, 1 — 88 из 90 |
| Профиль гейтов утверждает человек, зависимости ставятся до проверки базы | черновые гейты без зависимостей молча слабеют (п. 5) |
| Цену считать по приращению, а не по `total_cost_usd` при `--resume` | иначе оркестраторы выглядят дороже, чем есть (п. 3) |
